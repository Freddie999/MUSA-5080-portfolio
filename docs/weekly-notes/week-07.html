Week 7: Feature Engineering for Regression

Logs, squared terms, categories, interactions, and place fixed effects—building features and checking whether they improve predictions.
Published

October 9, 2026

What this week is about

This week builds on regression and cross-validation by changing how we represent the inputs to a model.

The main question is:

Can I help a regression model predict rent more accurately by changing the features I give it?

We work with Philadelphia census tracts and predict median monthly gross rent using median household income, renter share, building age, and location. We then try logs, squared terms, categories, interactions, and planning-district fixed effects.

1. What is a feature?

A feature is an input variable used by a model. income, bldg_age, and dist_ch_mi are features. rent is the outcome we want to predict.

Feature engineering means constructing or changing those inputs so they represent useful patterns. For example:

Original information Engineered feature Pattern it can represent
Household income log(income) Equal percentage changes rather than equal dollar changes
Building age bldg_age and bldg_age^2 A curved relationship
Distance to City Hall Core, Inner, or Outer ring Differences between groups
Income and ring log(income) * ring Different income slopes in different rings
Planning district A district factor Different average levels across places

A linear regression is linear in its coefficients. It can still represent a curve in an original variable:

\[ \widehat{rent} = \hat\beta_0 + \hat\beta_1 age + \hat\beta_2 age^2. \]

The coefficients are multiplied by features and added together. One of those features happens to be squared age.

We should have a reason for a feature, then check whether it helps prediction. More features and more complicated formulas do not automatically produce a better model.

The new columns translate the source data into useful predictors:

  • 2023 - yr_builtE is an approximate building-age measure based on a tract median. It is not the age of every building.
  • pct_renter runs from 0 to 100. A change from 40 to 41 is one percentage point.

Distance measurement: we measure from the tract polygon to the City Hall point. A tract containing City Hall has distance zero. For other tracts, this is the minimum straight-line distance from the polygon to that point. It is not distance from the tract centroid, a resident’s home, or a route along streets. Dividing US survey feet by 5,280 gives the classroom approximation in miles.

For a representative-point alternative, we could use st_point_on_surface() before computing distance. That would define a different feature and could change the model results.

case_when() checks conditions from top to bottom and takes the first match. Core means below 2 miles, Inner means 2 to below 5, and Outer means 5 or more. A tract at exactly 2 miles is Inner.

Having ten observations per group is a practical precaution, not a mathematical guarantee of safe ten-fold CV. What matters is whether every validation category also exists in that fold’s training data. We check that directly below.

4. Compare models fairly with cross-validation

Same rows, same folds, same units

A fair comparison keeps three things fixed:

  1. Rows: all candidate models are evaluated on the same tracts.
  2. Folds: each tract is held out in the same round for each candidate.
  3. Units: all RMSE values are calculated in monthly rent dollars.

If a model drops additional tracts, gets a luckier split, or is scored in different units, a lower number may not mean its features are better.

A reusable CV function

cv_rmse <- function(f, data, fold_id, log_outcome = FALSE) {
  stopifnot(length(fold_id) == nrow(data), !anyNA(fold_id))
  preds <- rep(NA_real_, nrow(data))

  for (k in sort(unique(fold_id))) {
    train_rows <- fold_id != k
    validation_rows <- fold_id == k

    fitted_model <- lm(
      f,
      data = data[train_rows, ],
      na.action = na.fail
    )

    p <- predict(fitted_model, newdata = data[validation_rows, ])

    if (log_outcome) {
      p <- exp(p)
    }

    preds[validation_rows] <- p
  }

  if (any(!is.finite(preds))) {
    stop("Cross-validation produced missing or non-finite predictions.")
  }

  sqrt(mean((data$rent - preds)^2))
}

Read this as a set of instructions:

  • f is a formula such as rent ~ income.
  • data is the table of observations.
  • fold_id says which fold each row belongs to. Passing it explicitly makes the function less dependent on objects elsewhere in the session.
  • Each loop fits on nine folds and predicts the held-out fold.
  • preds[validation_rows] <- p puts predictions back in their original row positions.
  • log_outcome = TRUE converts predicted log rent back to dollars.
  • Finally, the function returns one pooled out-of-fold RMSE.

\[ RMSE = \sqrt{\frac{1}{n}\sum_{i=1}^{n}(rent_i-\widehat{rent}_{i,\;held\ out})^2}. \]

Squaring penalizes large errors; taking the square root returns the result to dollars. Lower is better on this metric. RMSE is not an average percentage error, and it is not the same as mean absolute error.

na.action = na.fail prevents a candidate model from quietly dropping rows. The function uses pooled squared errors, which need not equal the simple average of ten separately computed fold RMSE values.

5. Log transformations

Why take a log?

R’s log() is the natural logarithm. It compresses large positive numbers and makes equal multiplicative changes equally spaced.

Moving from $20,000 to $40,000 doubles income. Moving from $100,000 to $200,000 also doubles it. Both moves have a log difference of log(2), although their dollar differences are very different.

Zeros and log1p()

log(0) produces negative infinity. log1p(x) means log(1 + x), so zero becomes zero. It is useful for nonnegative counts such as trees or service calls.

It is not a universal repair for every variable with zeros. Consider whether zero is meaningful, whether values can be negative, and whether a count, a dollar amount, or a proportion is being transformed. With log1p(x), the simple percentage interpretation concerns changes in 1 + x; it can differ substantially from changes in x near zero.

These describe the back-transformed fitted relationship; interpreting conditional means also requires attention to retransformation.

For pct_renter, one unit is one percentage point of renter share. That is different from a 1% relative increase in renter share.

A number such as 0.19 in log units is not directly better than $260. They measure different things, and these particular calculations are training errors rather than CV errors.

The CV helper uses exp(p) to undo the log before comparing predicted rent with observed rent. That makes the reported RMSE values comparable in dollars.

There is a further distinction: exponentiating a predicted log value is not generally the conditional mean on the original scale. With suitable log-error assumptions it corresponds to a conditional median. Here we use the simple back-transform. More advanced work can estimate a retransformation correction using each training fold only, then assess whether it improves held-out dollar predictions.

I() tells the formula to use the arithmetic result of bldg_age^2. Formula operators have special meanings in R; leaving out I() does not request the same squared numeric predictor.

For the age part of the prediction,

\[ \widehat{rent} = \cdots + b_1 age + b_2 age^2, \]

the local slope is

\[ b_1 + 2b_2 age. \]

So b1 alone is not a constant “effect of an extra year” at all ages. The exact predicted change from age a to a + 1 is b1 + b2 * (2*a + 1).

  • A positive squared coefficient makes a U-shaped curve.
  • A negative squared coefficient makes an upside-down U.
  • The turning point is -b1 / (2*b2) when the squared coefficient is nonzero.

Check whether the turning point is inside the observed range. The lecture reported about 76.8 years within a range of 5–85. That is a description of the fitted curve, not proof that renovating or aging a building causes that rent pattern.

Using the lecture’s reported coefficients, the Core slope was about 653.70 and the Outer adjustment about −244.42. The Outer slope was therefore about 409.28 per one-unit change in log income. For a 1% income increase, the approximate dollar changes were $6.54 in Core and $4.09 in Outer.

Interactions add parameters. Do not cross every predictor with every other predictor simply because R allows it. A reason for the interaction and held-out performance are both useful checks.

9. Fixed effects: allowing places to have different intercepts

A district fixed effect uses a factor to allow each district its own intercept. With an intercept and 18 represented districts, ordinary coding uses 17 district indicator coefficients.

The model can capture additive group-level differences that are shared within a district. It does not explain every unmeasured characteristic, eliminate all confounding, or model every difference among tracts within that district.

District codes are labels, not measurements

If district names were replaced by numbers 1 through 18 and entered as one numeric predictor, the model would assume a constant rent change for each one-number increase. District numbering has no such quantitative meaning.

Use factor(district). Likewise, do not treat ZIP codes or GEOIDs as continuous amounts. as.numeric() applied to a factor returns its internal level codes, not a meaningful measurement.

11. Limits and habits to keep

Predictions are not causal effects

“Tracts in this district have higher predicted rent” does not explain whether the difference comes from amenities, housing quality, demand, selection, or another factor. A spatial feature can describe an association more concretely than a district label without establishing causality.

ACS uncertainty has not disappeared

The outcome and predictors are survey estimates. We retained rent_moe, but ordinary lm() here does not automatically propagate ACS margins of error or correct measurement error in income. The charts and CV measure prediction of the available tract estimates under this workflow, not perfect knowledge of true rents.

Random tract folds answer a limited question

Nearby tracts may share conditions. Random folds can place neighboring tracts in both training and validation sets. Performance for new areas or a different city may be worse. Spatially separated validation answers a different question, and entirely held-out districts create a particular problem for district fixed effects.

Keep learned preprocessing inside training folds

The ring cutoffs in this lesson are preset. Taking log(x) or squaring x does not estimate parameters from the full sample. In contrast, imputation values, scaling parameters, data-chosen cutoffs, and feature selection should be learned within each training fold when used to assess prediction.

The district regrouping here follows the lecture’s full-sample, outcome-free geographic preparation. It is a classroom comparison for known places. For deployment, define the grouping rule in advance and make sure it also works for future observations.

Fit the final model after comparison

Each CV round produces a temporary model used to evaluate held-out predictions. We do not select whichever fold happened to perform best as the final fitted line. After choosing a specification, fit it to the intended training data and evaluate any reserved test set only when the specification is settled.

## What this week is about

This week builds on regression and cross-validation by changing how we represent the inputs to a model.

The main question is:

> Can I help a regression model predict rent more accurately by changing the features I give it?

We work with Philadelphia census tracts and predict **median monthly gross rent** using median household income, renter share, building age, and location. We then try logs, squared terms, categories, interactions, and planning-district fixed effects.

## 1. What is a feature?

A **feature** is an input variable used by a model. `income`, `bldg_age`, and `dist_ch_mi` are features. `rent` is the outcome we want to predict.

**Feature engineering** means constructing or changing those inputs so they represent useful patterns. For example:

| Original information | Engineered feature | Pattern it can represent |
|---|---|---|
| Household income | `log(income)` | Equal percentage changes rather than equal dollar changes |
| Building age | `bldg_age` and `bldg_age^2` | A curved relationship |
| Distance to City Hall | Core, Inner, or Outer ring | Differences between groups |
| Income and ring | `log(income) * ring` | Different income slopes in different rings |
| Planning district | A district factor | Different average levels across places |

A linear regression is **linear in its coefficients**. It can still represent a curve in an original variable:

$$
\widehat{rent} = \hat\beta_0 + \hat\beta_1 age + \hat\beta_2 age^2.
$$

The coefficients are multiplied by features and added together. One of those features happens to be squared age.

We should have a reason for a feature, then check whether it helps prediction. More features and more complicated formulas do not automatically produce a better model.

The new columns translate the source data into useful predictors:

- `2023 - yr_builtE` is an approximate building-age measure based on a tract median. It is not the age of every building.
- `pct_renter` runs from 0 to 100. A change from 40 to 41 is **one percentage point**.
- `na_if(hh_totalE, 0)` avoids dividing by zero.
- `is.finite()` excludes missing values, infinity, and undefined calculations.
- Positive rent and income are required because we will take their logs.

**Distance measurement:** we measure from the **tract polygon** to the City Hall point. A tract containing City Hall has distance zero. For other tracts, this is the minimum straight-line distance from the polygon to that point. It is not distance from the tract centroid, a resident's home, or a route along streets. Dividing US survey feet by 5,280 gives the classroom approximation in miles.

For a representative-point alternative, we could use `st_point_on_surface()` before computing distance. That would define a different feature and could change the model results.

## 4. Compare models fairly with cross-validation

### Same rows, same folds, same units

A fair comparison keeps three things fixed:

1. **Rows:** all candidate models are evaluated on the same tracts.
2. **Folds:** each tract is held out in the same round for each candidate.
3. **Units:** all RMSE values are calculated in monthly rent dollars.

If a model drops additional tracts, gets a luckier split, or is scored in different units, a lower number may not mean its features are better.

```{r}
#| label: week7-create-folds

model_data <- tracts %>% st_drop_geometry()

set.seed(5080)
folds <- sample(rep(1:10, length.out = nrow(model_data)))

table(folds)

coverage_check <- map_dfr(1:10, function(k) {
  map_dfr(c("ring", "district_cv"), function(v) {
    training_levels <- unique(as.character(model_data[[v]][folds != k]))
    validation_levels <- unique(as.character(model_data[[v]][folds == k]))

    tibble(
      fold = k,
      variable = v,
      unseen_levels = paste(
        setdiff(validation_levels, training_levels),
        collapse = ", "
      )
    )
  })
})

coverage_check %>% filter(unseen_levels != "")

if (any(coverage_check$unseen_levels != "")) {
  stop("A validation group is absent from training. Revisit grouping or fold design.")
}
```

An empty coverage table is good: it means there are no unseen `ring` or `district_cv` levels in the validation folds.

`rep(1:10, length.out = ...)` repeats fold numbers until every tract has one. `sample()` shuffles their assignment. `set.seed()` makes the assignment repeatable for the same ordered data. Do not reorder or remove rows after this step without rebuilding the folds for every model.

### A reusable CV function

```{r}
#| label: week7-cv-helper

cv_rmse <- function(f, data, fold_id, log_outcome = FALSE) {
  stopifnot(length(fold_id) == nrow(data), !anyNA(fold_id))
  preds <- rep(NA_real_, nrow(data))

  for (k in sort(unique(fold_id))) {
    train_rows <- fold_id != k
    validation_rows <- fold_id == k

    fitted_model <- lm(
      f,
      data = data[train_rows, ],
      na.action = na.fail
    )

    p <- predict(fitted_model, newdata = data[validation_rows, ])

    if (log_outcome) {
      p <- exp(p)
    }

    preds[validation_rows] <- p
  }

  if (any(!is.finite(preds))) {
    stop("Cross-validation produced missing or non-finite predictions.")
  }

  sqrt(mean((data$rent - preds)^2))
}
```

Read this as a set of instructions:

- `f` is a formula such as `rent ~ income`.
- `data` is the table of observations.
- `fold_id` says which fold each row belongs to. Passing it explicitly makes the function less dependent on objects elsewhere in the session.
- Each loop fits on nine folds and predicts the held-out fold.
- `preds[validation_rows] <- p` puts predictions back in their original row positions.
- `log_outcome = TRUE` converts predicted log rent back to dollars.
- Finally, the function returns one pooled out-of-fold RMSE.

$$
RMSE = \sqrt{\frac{1}{n}\sum_{i=1}^{n}(rent_i-\widehat{rent}_{i,\;held\ out})^2}.
$$

Squaring penalizes large errors; taking the square root returns the result to dollars. Lower is better on this metric. RMSE is not an average percentage error, and it is not the same as mean absolute error.

`na.action = na.fail` prevents a candidate model from quietly dropping rows. The function uses pooled squared errors, which need not equal the simple average of ten separately computed fold RMSE values.

## 5. Log transformations

### Why take a log?

R's `log()` is the natural logarithm. It compresses large positive numbers and makes equal **multiplicative** changes equally spaced.

Moving from $20,000 to $40,000 doubles income. Moving from $100,000 to $200,000 also doubles it. Both moves have a log difference of `log(2)`, although their dollar differences are very different.

```{r}
#| label: week7-income-histograms
#| fig-width: 10
#| fig-height: 4

p_income <- ggplot(model_data, aes(x = income)) +
  geom_histogram(bins = 40, fill = "steelblue", color = "white") +
  scale_x_continuous(labels = scales::label_dollar()) +
  labs(title = "Original income", x = "Annual median household income", y = "Tracts")

p_log_income <- ggplot(model_data, aes(x = log(income))) +
  geom_histogram(bins = 40, fill = "darkorange", color = "white") +
  labs(title = "Logged income", x = "Natural log of income", y = "Tracts")

p_income + p_log_income
```

The log may reduce a long right tail. But a predictor does **not** have to be normally distributed for linear regression. We use the plot to consider a plausible relationship and then test prediction performance; skew alone does not prove that logging is the right choice.

### Log the predictor: rent in dollars, income in logs


For a model containing `b * log(income)`, a 1% income increase corresponds to approximately `b / 100` dollars more predicted rent, holding other predictors fixed. The exact change is `b * log(1.01)`.

### Zeros and `log1p()`

```{r}
#| label: week7-log-zero-demo

log(0)
log1p(c(0, 1, 10, 100))
```

`log(0)` produces negative infinity. `log1p(x)` means `log(1 + x)`, so zero becomes zero. It is useful for nonnegative counts such as trees or service calls.

It is not a universal repair for every variable with zeros. Consider whether zero is meaningful, whether values can be negative, and whether a count, a dollar amount, or a proportion is being transformed. With `log1p(x)`, the simple percentage interpretation concerns changes in **1 + x**; it can differ substantially from changes in `x` near zero.

### Log the outcome as well

```{r}
#| label: week7-log-outcome

f_logy <- log(rent) ~ log(income) + pct_renter + bldg_age + dist_ch_mi

```

| Form | Formula | Interpretation, holding other predictors fixed |
|---|---|---|
| Level–level | `y ~ x` | One more unit of X corresponds to β more units of Y. |
| Level–log | `y ~ log(x)` | A 1% increase in X corresponds to approximately β/100 more units of Y. |
| Log–level | `log(y) ~ x` | One more unit of X corresponds to approximately 100β% change in Y. |
| Log–log | `log(y) ~ log(x)` | A 1% increase in X corresponds to approximately β% change in Y. |

In a log–level model, the exact modeled percentage change for one unit of X is `100 * (exp(b) - 1)`. In a log–log model, a 10% increase in X corresponds to `100 * (1.10^b - 1)` percent change. These describe the back-transformed fitted relationship; interpreting conditional means also requires attention to retransformation.

For `pct_renter`, one unit is **one percentage point of renter share**. That is different from a 1% relative increase in renter share.

### Do not compare log-scale errors with dollar errors

```{r}
#| label: week7-rmse-units

tibble(
  calculation = c("Baseline training RMSE", "Logged-outcome training RMSE"),
  value = c(
    sqrt(mean(residuals(m0)^2)),
    sqrt(mean(residuals(m_logy)^2))
  ),
  units = c("Monthly rent dollars", "Log rent units")
)
```

A number such as 0.19 in log units is not directly better than $260. They measure different things, and these particular calculations are training errors rather than CV errors.

The CV helper uses `exp(p)` to undo the log before comparing predicted rent with observed rent. That makes the reported RMSE values comparable in dollars.

There is a further distinction: exponentiating a predicted log value is not generally the conditional **mean** on the original scale. With suitable log-error assumptions it corresponds to a conditional median. Here we use the simple back-transform. More advanced work can estimate a retransformation correction using each training fold only, then assess whether it improves held-out dollar predictions.

### Fit the squared term

```{r}

coef(m_sq)[c("bldg_age", "I(bldg_age^2)")]

b2 <- unname(coef(m_sq)["I(bldg_age^2)"])

  maximum_observed_age = max(model_data$bldg_age)

  )
```

`I()` tells the formula to use the arithmetic result of `bldg_age^2`. Formula operators have special meanings in R; leaving out `I()` does not request the same squared numeric predictor.

For the age part of the prediction,

$$
\widehat{rent} = \cdots + b_1 age + b_2 age^2,
$$

the local slope is

$$
b_1 + 2b_2 age.
$$

So `b1` alone is not a constant “effect of an extra year” at all ages. The exact predicted change from age `a` to `a + 1` is `b1 + b2 * (2*a + 1)`.

- A positive squared coefficient makes a U-shaped curve.
- A negative squared coefficient makes an upside-down U.
- The turning point is `-b1 / (2*b2)` when the squared coefficient is nonzero.

Check whether the turning point is inside the observed range. The lecture reported about 76.8 years within a range of 5–85. That is a description of the fitted curve, not proof that renovating or aging a building causes that rent pattern.

## 7. Categories and reference groups

### How R represents a factor

```{r}
#| label: week7-factor-matrix

model.matrix(~ ring, data = model_data) %>% head(8)
```

With an intercept and ordinary treatment coding, three ring categories become two indicator columns:

| Ring | Intercept | `ringInner` | `ringOuter` |
|---|---:|---:|---:|
| Core | 1 | 0 | 0 |
| Inner | 1 | 1 | 0 |
| Outer | 1 | 0 | 1 |

Core is the reference. Including all three indicators **and** an intercept would introduce exact redundancy. R handles this coding when the predictor is a factor. A deliberately specified no-intercept model is a different coding choice; the “k minus one” rule assumes the usual intercept model.

### Replace continuous distance with rings

## 9. Fixed effects: allowing places to have different intercepts

A district fixed effect uses a factor to allow each district its own intercept. With an intercept and 18 represented districts, ordinary coding uses 17 district indicator coefficients.

The model can capture **additive group-level differences** that are shared within a district. It does not explain every unmeasured characteristic, eliminate all confounding, or model every difference among tracts within that district.

### District codes are labels, not measurements

If district names were replaced by numbers 1 through 18 and entered as one numeric predictor, the model would assume a constant rent change for each one-number increase. District numbering has no such quantitative meaning.

Use `factor(district)`. Likewise, do not treat ZIP codes or GEOIDs as continuous amounts. `as.numeric()` applied to a factor returns its internal level codes, not a meaningful measurement.

Residual means **observed rent minus predicted rent**:

- Red: positive residual, so the model underpredicted rent.
- Blue: negative residual, so the model overpredicted rent.
- Near white: the prediction is close to the observed value.

Both maps use identical color limits so equal colors mean equal dollar residuals. These are **in-sample residuals**. Less visible clustering is a diagnostic clue, not proof of improved prediction, spatial independence, or a causal explanation.

`.data[[var]]` selects a column using the text stored in `var`. When the function receives `"resid_fe"`, it maps the `resid_fe` column to fill color.

```{r}
f_fe_cv <- rent ~ log(income) + pct_renter + bldg_age + I(bldg_age^2) + district_cv

model_log <- model_log %>%
  add_row(

  )
```

The original-district model in the maps and the `district_cv` model in the log are related but **not identical**. Keep that distinction when describing the results.

Fixed effects are useful when predicting another observation in a known group. They cannot directly supply a learned intercept for a completely new district. Measured spatial features, such as distance to transit, can be computed in new places, but their relationships may still fail to transfer. Neither approach automatically establishes why rent differs.

## 11. Limits and habits to keep

### Predictions are not causal effects

“Tracts in this district have higher predicted rent” does not explain whether the difference comes from amenities, housing quality, demand, selection, or another factor. A spatial feature can describe an association more concretely than a district label without establishing causality.

### ACS uncertainty has not disappeared

The outcome and predictors are survey estimates. We retained `rent_moe`, but ordinary `lm()` here does not automatically propagate ACS margins of error or correct measurement error in income. The charts and CV measure prediction of the available tract estimates under this workflow, not perfect knowledge of true rents.

### Random tract folds answer a limited question

Nearby tracts may share conditions. Random folds can place neighboring tracts in both training and validation sets. Performance for new areas or a different city may be worse. Spatially separated validation answers a different question, and entirely held-out districts create a particular problem for district fixed effects.

### Keep learned preprocessing inside training folds

The ring cutoffs in this lesson are preset. Taking `log(x)` or squaring `x` does not estimate parameters from the full sample. In contrast, imputation values, scaling parameters, data-chosen cutoffs, and feature selection should be learned within each training fold when used to assess prediction.

The district regrouping here follows the lecture's full-sample, outcome-free geographic preparation. It is a classroom comparison for known places. For deployment, define the grouping rule in advance and make sure it also works for future observations.

### Fit the final model after comparison

Each CV round produces a temporary model used to evaluate held-out predictions. We do not select whichever fold happened to perform best as the final fitted line. After choosing a specification, fit it to the intended training data and evaluate any reserved test set only when the specification is settled.
