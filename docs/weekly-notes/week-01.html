Week 1: Getting Set Up

Understanding websites, Quarto, R, and GitHub Pages.
Published

August 28, 2026

What We Did

This week, I set up the workflow for my MUSA portfolio. I created a repository from a template, cloned it using GitHub Desktop, edited files in RStudio, rendered my Quarto files, and published the resulting website with GitHub Pages.

The basic workflow is:

Edit → Save → Render → Commit → Push → Refresh

What Is a Website?

A website is a collection of files that a browser can display. These files usually include:

  • HTML, which provides the structure
  • CSS, which controls the appearance
  • JavaScript, which adds interactivity
  • Images and other supporting files

My portfolio is made from written source files and then converted into HTML pages by Quarto. GitHub Pages hosts those HTML files so that other people can view them online.

A simple mental model is:

Quarto creates the website, and GitHub Pages publishes it.

What Is Quarto?

Quarto is a publishing system that converts files written in .qmd format into HTML documents and other outputs such as PDFs, reports, presentations, books, and websites.

A .qmd file combines three things:

  1. YAML, which contains document settings
  2. Markdown, which contains my written content
  3. Code chunks, which run code and display the results

Quarto is useful because it allows writing, coding, analysis, and presentation to exist in the same document.

How Quarto Works

When I click Render, Quarto processes the .qmd file from top to bottom.

Behind the scenes, it:

  1. Reads the document settings in the YAML section.
  2. Interprets the Markdown text.
  3. Finds the code chunks.
  4. Sends R code to R for evaluation.
  5. Receives the results from R.
  6. Combines my writing, code, and results.
  7. Produces an HTML file.

The result is a finished webpage that can be viewed in a browser.

Anatomy of a .qmd File

A Quarto document usually looks like this:

---
title: "Week 1 Notes"
date: 2026-08-28
---

This first section is called YAML. It contains metadata and settings for the document.

The body of the document contains Markdown:

## What I Learned

Quarto lets me combine written explanations with executable R code.

[Visit my portfolio](index.qmd)

The document can also contain an R code chunk:

2 + 2
[1] 4

When the document is rendered, the result of the calculation appears underneath the code.

Files and Folders

Different files in the project serve different purposes.

Files for the website

  • index.qmd is the homepage.
  • about.qmd is the About page.
  • weekly-notes/ contains my weekly notes.
  • assignments/ contains my assignments.

Files for the tools

  • _quarto.yml contains settings for the entire Quarto website.
  • freeze/ stores rendered results so that some code does not need to run again.
  • .Rproj identifies the project as an RStudio project.
  • .gitignore tells Git which files it should ignore.
  • .Renviron stores environment variables and private information such as API keys.
  • docs/ contains the HTML files generated by Quarto for publication.

The files I write are the source files. The files in docs/ are the rendered website.

How Pages Become Website URLs

The homepage file is usually named index.qmd. When Quarto renders the website, it creates:

docs/index.html

GitHub Pages then displays that file at the main website address.

The same pattern applies to folders:

weekly-notes/index.qmd
        ↓
docs/weekly-notes/index.html
        ↓
myname.github.io/weekly-notes/

The index file acts as the default page for its folder.

Git, GitHub, and GitHub Desktop

These three tools are related, but they are not the same thing.

Git

Git is a version-control system that runs on my computer. It records changes to files and allows me to save labelled snapshots of my work.

GitHub.com

GitHub.com is an online service that stores a copy of my project repository. It also makes the project accessible for collaboration and publishing.

GitHub Desktop

GitHub Desktop is a graphical interface for Git. It provides buttons for common Git actions.

Two important Git actions are:

  • Commit: Save a labelled snapshot of changes on my computer.
  • Push: Send those committed changes to GitHub.com.

After I push changes, GitHub Pages can update the live version of my portfolio.

R Scripts and Quarto Documents

An R script contains mainly R code:

x <- 10
x + 5

A Quarto document is more flexible. It can contain:

  • Written explanations
  • Headings
  • Links
  • Images
  • R code
  • Tables
  • Charts
  • Code results

This makes Quarto useful for documenting not only what I calculated, but also why I calculated it and what the results mean.

My Mental Model

I now think of my portfolio as having three versions:

  1. My computer: where I edit the source files
  2. GitHub.com: where Git stores and tracks the project
  3. My live website: what visitors see in their browser

The complete process is:

Write or edit a .qmd file
        ↓
Render it with Quarto
        ↓
Review the generated HTML
        ↓
Commit the changes with Git
        ↓
Push the commit to GitHub
        ↓
GitHub Pages updates the website

Reflection

This week helped me understand that my portfolio is not created directly in the browser. I write source files in Quarto, render them into HTML, and then use GitHub Pages to publish the result. The most important idea for me was separating the source files from the finished website. I am still building confidence with the workflow, but I now have a clearer understanding of how R, Quarto, Git, GitHub, and GitHub Pages work together.

Questions I Still Have

  • How can I customize the visual design of my Quarto website?
  • How can I add interactive maps and visualizations?
  • How can I organize larger projects with many data files and code chunks?
