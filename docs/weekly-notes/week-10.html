Week 10: Geographic Cross-Validation and Logistic Regression

Testing spatial predictions, interpreting probabilities and odds, and choosing decision thresholds.
Author

Frederick Abalo

Published

November 6, 2026

What connects this week’s topics?

Our modeling workflow is still:

Define the outcome → choose the unit of analysis → build features → fit a model → validate it → make predictions → decide what to do.

This week covered two parts of that workflow:

  1. Geographic cross-validation: how well does a spatial model predict an area that was left out of training?
  2. Logistic regression and thresholds: how do we predict a binary outcome, interpret the probability, and decide which cases to flag?

These are separate examples. The geographic example uses burglary counts in grid cells. The logistic example uses whether a person was rearrested within two years.

Earlier work Unit of analysis Outcome Model Prediction
House prices A house Sale price Linear regression Dollars
Burglary patterns A grid cell Number of burglaries Poisson regression Expected count
Rearrest A person Rearrest within two years: 0 or 1 Logistic regression Probability

The model should suit the outcome. Counts cannot be negative, and probabilities cannot be below 0 or above 1.

Geographic cross-validation

Why can random folds be too optimistic?

In random cross-validation, observations are assigned to folds without regard to location. A test cell may be surrounded by training cells.

Nearby places often have similar features and outcomes. This is the connection to spatial autocorrelation and Tobler’s idea that nearby things tend to be more related than distant things. Two neighboring cells may also have almost identical distances to a hotspot.

As a result, a random split can make performance look better than it would be when predicting a whole new area. The lecture described this as proximity leakage: the model has learned from very similar places next door.

The relevant question is what kind of prediction we want to test. Predicting another cell among known neighboring cells is different from predicting an entire district that was excluded from training.

Hold out whole districts

Geographic cross-validation groups cells by area. In the class example, the areas are police districts:

  • Hold out one district as the test set.
  • Train on cells in all the other districts.
  • Predict the held-out district and calculate its error.
  • Repeat until every district has been held out once.

The test district must not contribute to fitting the model for its own fold. Holding out districts reduces the close mixing of training and test locations, although it does not guarantee that all spatial dependence disappears across district boundaries.

Step 1: assign each cell to a district

The spatial example uses the lab’s fishnet and police_districts objects. fishnet contains grid cells and model variables; police_districts contains district polygons. The following examples describe that workflow using sf and tidyverse functions.

cell_district <- st_centroid(fishnet) %>%
  st_join(police_districts %>% select(district = dist_num)) %>%
  st_drop_geometry() %>%
  select(cell_id, district)

fishnet <- fishnet %>%
  left_join(cell_district, by = "cell_id") %>%
  filter(!is.na(district))

What each step does:

  • st_centroid(fishnet) represents each grid cell by a point at its centroid.
  • select(district = dist_num) keeps the district identifier and renames it district. The polygon geometry remains attached to the sf object.
  • st_join() assigns district attributes using the spatial relationship between the centroid and district polygons.
  • st_drop_geometry() removes geometry after we have obtained the district identifier.
  • select(cell_id, district) keeps a lookup table linking cell IDs to districts.
  • left_join(..., by = "cell_id") attaches the district identifier to the original grid cells.
  • filter(!is.na(district)) removes cells without a matched district.

The centroid gives us a consistent way to assign a cell that overlaps a district boundary. It is still worth checking for duplicate assignments: a centroid exactly on a shared boundary, or overlapping district polygons, can match more than one polygon.

Both spatial layers need compatible coordinate reference systems. The cell ID connects the lookup table back to the original cells; row order is not the matching rule.

Step 2: train and test one district at a time

districts <- unique(fishnet$district)

cv_results <- map_dfr(districts, function(d) {
  train <- fishnet %>%
    filter(district != d) %>%
    st_drop_geometry()

  test <- fishnet %>%
    filter(district == d) %>%
    st_drop_geometry()

  fit <- glm(
    burglaries ~ cars_cnt + log_light_nn1 + log_graffiti_nn3 +
      loop_mi + dist_hotspot,
    family = poisson,
    data = train
  )

  test %>%
    mutate(pred = predict(fit, newdata = test, type = "response")) %>%
    summarize(
      district = d,
      n_cells = n(),
      mae = mean(abs(burglaries - pred))
    )
})

Read d as “the district being held out this time.”

unique() gets the district identifiers. map_dfr() runs the function for each identifier and stacks the returned rows into one table. function(d) is an anonymous function: it defines steps without assigning the function a separate name.

Inside each run:

  • district != d means every district except the current one: training data.
  • district == d means only the current district: test data.
  • glm(..., family = poisson) fits the burglary-count model on the training data.
  • newdata = test requests predictions for cells excluded from fitting.
  • type = "response" returns expected burglary counts rather than log expected counts.
  • summarize() returns one row for that held-out district.

The formula retains the predictor names from the class example. The + signs inside a model formula add predictors; they do not add the columns together into one predictor.

What does MAE measure?

\[ \operatorname{MAE} = \frac{1}{n}\sum_{i=1}^{n}|y_i - \hat y_i| \]

In mean(abs(burglaries - pred)), we subtract the predicted count from the observed count, take the absolute value of each error, and average those errors.

If a district’s MAE were 2, its predictions would be off by an average of two burglaries per cell. This is an illustration of the units, not a result from the district data.

n_cells matters too. An error calculated from a small district fold may be less stable than one calculated from many cells.

Step 3: map the errors

police_districts %>%
  left_join(cv_results, by = c("dist_num" = "district")) %>%
  ggplot() +
  geom_sf(aes(fill = mae), color = "white") +
  scale_fill_viridis_c(name = "MAE") +
  theme_void()

The join matches dist_num in the district polygons to district in the results. geom_sf() draws the polygons, while aes(fill = mae) maps prediction error to color.

This is a map of where the model predicts poorly, not a map of where burglary counts are highest. Those are different questions. Cross-validation also does not correct problems in how the outcome was recorded.

Generalized linear models: keeping predictions within their limits

A generalized linear model, or GLM, combines:

  1. A distribution for the outcome, conditional on its predictors.
  2. A linear predictor, such as \(z = \beta_0 + \beta_1x_1 + \beta_2x_2\).
  3. A link function connecting the expected outcome to that linear predictor.

The word is model, not “module.”

Link and inverse link

The link function transforms the expected outcome onto the scale of the linear predictor. The inverse link converts the linear predictor back into an expected count or probability.

Model Outcome Expected value Link: expected value to \(z\) Inverse link: \(z\) to expected value
Poisson A nonnegative integer count \(\mu > 0\) \(\log(\mu) = z\) \(\mu = e^z\)
Logistic A binary value, 0 or 1 \(0 < p < 1\) \(\log\left(\frac{p}{1-p}\right) = z\) \(p = \frac{1}{1+e^{-z}}\)

Poisson uses an exponential inverse link. Logistic uses the sigmoid inverse link. These are not interchangeable.

The probability or expected count can be non-integer even when the observed outcome is binary or a count. An expected count of 2.4 is valid; an observed count of 2.4 burglaries is not. A predicted probability of 0.7 is valid; the observed binary outcome is still 0 or 1.

For logistic regression, the link transforms the probability, not the observed zeros and ones. We do not manually take the logit of each observed 0 or 1 and fit an ordinary linear regression.

Why not ordinary linear regression for this example?

An ordinary linear model can predict values below 0 or above 1 when fitted to a binary outcome. Such values cannot be interpreted as probabilities.

Logistic regression keeps the additive structure of the predictors but changes the scale on which that structure is modeled. Its inverse link produces valid probabilities.

“Linear” refers to the linear predictor. It does not mean that probability changes along a straight line as a predictor increases.

The class example: rearrest within two years

The slides use ProPublica’s COMPAS dataset from Broward County, Florida. The relevant records concern people screened in 2013–2014, with a two-year follow-up.

Our outcome is two_year_recid:

  • 1: rearrest recorded within two years.
  • 0: no rearrest recorded within that follow-up.

A recorded arrest is not the same as an observed crime. The model predicts the recorded outcome in this dataset. It does not establish whether someone committed an unrecorded crime, or whether a recorded arrest led to a conviction.

The class fits a logistic regression using this dataset. This fitted model is not the proprietary COMPAS scoring algorithm itself.

Probability, odds, and log-odds

These are three ways to express related information. Keeping their scales separate makes the model easier to interpret.

Probability

Probability compares the event to all possible outcomes:

\[ p = \frac{\text{events}}{\text{events} + \text{non-events}} \]

A probability of 0.8 means 80 events per 100 cases in the corresponding frequency interpretation.

Odds

Odds compare the event to the non-event:

\[ \text{odds} = \frac{p}{1-p} \]

Probability Odds Interpretation
\(0.8\) \(0.8 / 0.2 = 4\) Four events for every one non-event
\(0.5\) \(0.5 / 0.5 = 1\) One event for every one non-event: even odds
\(0.1\) \(0.1 / 0.9 \approx 0.111\) About one event for every nine non-events
\(0.455\) \(0.455 / 0.545 \approx 0.835\) About 84 events for every 100 non-events

For the class data, the last row means about 84 people rearrested for every 100 people not rearrested. It does not mean 84 out of every 100 people were rearrested.

To convert odds back to probability:

\[ p = \frac{\text{odds}}{1 + \text{odds}} \]

Odds of 4 therefore correspond to \(4/(1+4)=0.8\).

These formulas compare an event with its alternative. They do not tell us whether a previous event changes the probability of the next event; that requires information about how the events are related.

Log-odds: the logit

Take the natural logarithm of the odds:

\[ \operatorname{logit}(p) = \log\left(\frac{p}{1-p}\right) \]

In R, log() uses the natural logarithm by default. exp() reverses the natural logarithm.

probability_ladder <- tibble(
  probability = c(0.01, 0.10, 0.50, 0.80, 0.90, 0.99)
) %>%
  mutate(
    odds = probability / (1 - probability),
    log_odds = log(odds)
  )

knitr::kable(probability_ladder, digits = 3)

For probabilities strictly between 0 and 1:

Quantity Range
Probability Between 0 and 1
Odds Positive, with no upper limit
Log-odds Any real number: negative, zero, or positive

This last range matches what a linear predictor can produce.

  • \(p=0.5\) gives odds of 1 and log-odds of 0.
  • \(p<0.5\) gives odds below 1 and negative log-odds.
  • \(p>0.5\) gives odds above 1 and positive log-odds.

At probabilities exactly 0 and 1, the logit is not finite. A finite logistic linear predictor returns a probability strictly between those endpoints.

From the linear predictor to the S-curve

The logistic model is:

\[ \log\left(\frac{p}{1-p}\right) = \beta_0 + \beta_1x_1 + \beta_2x_2 + \cdots = z \]

The inverse link converts \(z\) to probability:

\[ p = \frac{e^z}{1+e^z} = \frac{1}{1+e^{-z}} \]

These two expressions are equivalent. The resulting S-shaped curve is the sigmoid.

Linear predictor Predicted probability
\(z<0\) Below 50%
\(z=0\) Exactly 50%
\(z>0\) Above 50%

A negative \(z\) is valid. It is a negative log-odds, not a negative probability.

sigmoid_data <- tibble(z = seq(-6, 6, length.out = 301)) %>%
  mutate(probability = 1 / (1 + exp(-z)))

ggplot(sigmoid_data, aes(x = z, y = probability)) +
  geom_line(color = "steelblue", linewidth = 1) +
  geom_hline(yintercept = 0.5, linetype = "dashed", color = "grey50") +
  geom_vline(xintercept = 0, linetype = "dashed", color = "grey50") +
  scale_y_continuous(labels = scales::label_percent(), limits = c(0, 1)) +
  labs(
    title = "From log-odds to probability",
    x = "Linear predictor z (log-odds)",
    y = "Predicted probability"
  ) +

The curve is steepest in the middle and flatter near 0 and 1. The same increase in log-odds can therefore produce different changes in probability depending on where we start.

The distribution and the link have different jobs. The link connects the expected outcome to the predictors. The binomial distribution describes the binary outcome’s variation around its probability. A person with a predicted probability of 0.78 still has an observed outcome of either 0 or 1.

Logistic regression estimates coefficients by maximum likelihood: it selects coefficients that make the observed sequence of zeros and ones most likely under the model. This differs from ordinary least squares, which minimizes squared residuals.

The class evaluates classification with confusion-matrix measures rather than relying on the usual OLS fit summary. A good training fit alone does not establish performance on new people.

Read a coefficient three ways

1. Change in log-odds

The class model’s coefficient for priors_count is about 0.160.

Holding the other predictors fixed, one additional prior record is associated with an increase of about 0.160 in the log-odds of rearrest.

A coefficient is one contribution to the linear predictor. It is not the person’s full predicted log-odds; that requires the intercept and all the predictor contributions.

2. Change in odds

Exponentiate a logistic coefficient to obtain an odds ratio:

\[ \text{odds ratio} = e^{\beta} \]

ImportantOdds and odds ratios answer different questions

Odds above 1 mean the event is more likely than the non-event: \(p>0.5\).

An odds ratio above 1 means the odds increase relative to the comparison. It does not mean the resulting probability exceeds 50%.

For example, odds can increase from 0.25 to 0.50. The odds ratio is 2, but the probability only rises from 20% to about 33.3%. Both probabilities remain below 50%.

Likewise, a positive individual coefficient does not guarantee that a person’s full linear predictor is positive.

Exponentiating a Poisson coefficient gives a multiplier for the expected count, or rate when exposure is handled appropriately. Exponentiating a logistic coefficient gives a multiplier for the odds. The calculation looks the same, but the interpretation differs.

3. Change in predicted probability

An odds ratio of 1.17 does not mean an increase of 17 percentage points, or necessarily a 17% increase in probability.

From a probability to a decision

The model returns a probability. A threshold converts it to a binary label:

\[ \widehat{\text{class}} = \begin{cases} 1 & \text{if } \hat p \geq t,\\ 0 & \text{if } \hat p < t. \end{cases} \]

Here, \(t\) is the threshold. A probability of 0.45 is labeled positive at a threshold of 0.30 and negative at a threshold of 0.50.

Changing the threshold changes the decision, not the probability or the person’s observed outcome. It also does not refit the model.

A threshold of 0.50 is a common default, not a universal rule. The base rate gives context, but the consequences of errors and the available resources also matter.

compas <- compas %>%
  mutate(
    pred_30 = as.integer(p_hat >= 0.30),
    pred_50 = as.integer(p_hat >= 0.50),
    pred_70 = as.integer(p_hat >= 0.70)
  )

table(
  predicted = compas$pred_30,
  actual = compas$two_year_recid
)
         actual
predicted    0    1
        0 1047  282
        1 2316 2527

p_hat >= 0.30 returns a logical result for each person. as.integer() changes TRUE to 1 and FALSE to 0. A probability exactly equal to the threshold is classified as positive here.

The confusion matrix

A confusion matrix compares the predicted label with the actual recorded outcome.

Actual positive: rearrested Actual negative: not rearrested
Predicted positive: flagged True positive (TP) False positive (FP)
Predicted negative: not flagged False negative (FN) True negative (TN)

“Positive” means the outcome coded 1. It does not mean good, desirable, or morally positive.

  • TP: we flagged someone who was rearrested.
  • FP: we flagged someone who was not rearrested.
  • FN: we did not flag someone who was rearrested.
  • TN: we did not flag someone who was not rearrested.

R’s table() usually displays 0 before 1. Use the row and column labels to identify the cells rather than memorizing a position on the page.

Sensitivity, specificity, precision, and accuracy

Measure Formula Question
Sensitivity \(TP/(TP+FN)\) Of everyone actually positive, how many did we catch?
Specificity \(TN/(TN+FP)\) Of everyone actually negative, how many did we correctly leave unflagged?
Precision \(TP/(TP+FP)\) Of everyone we flagged, how many were actually positive?
Accuracy \((TP+TN)/(TP+FP+FN+TN)\) Of all cases, how many labels were correct?

Sensitivity and precision both have TP on top, but they answer different questions:

  • Sensitivity starts with all actual positives.
  • Precision starts with all predicted positives.

Using the disease analogy: sensitivity asks how many sick people we caught; precision asks how many people sent to quarantine were actually sick.

The classroom threshold exercise

Each participant had a predicted disease probability. A red dot indicated actual disease, and a star indicated the severe variant. Moving people to the quarantine area represented classifying them as positive.

The numerical example below is the 40-person example in the slides. The spoken activity used the people present in class, so its counts should not be combined with this table.

classroom_results <- tibble(

At 0.70, we quarantine only two people who are not sick, but miss nine of the 16 sick people.

Accuracy is highest at 0.70 in this example, even though that threshold misses the most sick people. The highest overall accuracy does not automatically give the most appropriate decision.

One starred case is missed at all three tested thresholds. Lowering the threshold further might catch that case, but also flag many more people. Changing the cutoff does not improve the model’s ordering of cases or correct the underlying predicted probabilities.

What changes when we move the threshold?

For a fixed set of predicted probabilities:

Threshold change Predicted positives Sensitivity Specificity
Lower the threshold More, or the same number Increases or stays the same Decreases or stays the same
Raise the threshold Fewer, or the same number Decreases or stays the same Increases or stays the same

Precision and overall accuracy do not have to move in one direction as the threshold changes.

Attach a policy decision to the label

The class compared two possible uses of the same probability:

Use What being flagged means Concern about false positives Concern about false negatives
Restrictive action Detention or denial of release Restricting someone who did not experience the recorded outcome Missing someone who did experience it
Supportive action An offer of housing help, a job program, or a case worker Using limited program capacity on additional people Failing to offer support to people who may benefit

The costs of errors are different across these uses. A lower threshold flags more people and may be appropriate for a broad offer of support if resources allow it. A restrictive action raises much more serious concerns about false positives, and the program itself may need to be questioned.

A person who was not rearrested does not necessarily have no need for support. Similarly, the observed outcome does not tell us what would have happened under a different intervention. Prediction alone does not establish the effect of providing services or detention.

The classroom discussion also asked whether a threshold could make both kinds of error disappear. Moving the threshold usually trades one type of error against another. Choosing a cutoff therefore requires a clear understanding of the action, the consequences, and whose costs count.

The threshold is a policy choice. glm() does not make that choice for us.

Leaving race out is not the same as removing bias

Race is not a predictor in this class formula. That alone does not establish that the model is race-blind or fair. Other variables can be associated with race, and arrest records reflect how the outcome was observed and recorded.

## Geographic cross-validation

### Why can random folds be too optimistic?

In random cross-validation, observations are assigned to folds without regard to location. A test cell may be surrounded by training cells.

Nearby places often have similar features and outcomes. This is the connection to **spatial autocorrelation** and Tobler's idea that nearby things tend to be more related than distant things. Two neighboring cells may also have almost identical distances to a hotspot.

As a result, a random split can make performance look better than it would be when predicting a whole new area. The lecture described this as **proximity leakage**: the model has learned from very similar places next door.

The relevant question is what kind of prediction we want to test. Predicting another cell among known neighboring cells is different from predicting an entire district that was excluded from training.

### Hold out whole districts

Geographic cross-validation groups cells by area. In the class example, the areas are police districts:

- Hold out one district as the test set.
- Train on cells in all the other districts.
- Predict the held-out district and calculate its error.
- Repeat until every district has been held out once.

The test district must not contribute to fitting the model for its own fold. Holding out districts reduces the close mixing of training and test locations, although it does not guarantee that all spatial dependence disappears across district boundaries.

### Step 1: assign each cell to a district

The spatial example uses the lab's `fishnet` and `police_districts` objects. `fishnet` contains grid cells and model variables; `police_districts` contains district polygons. The following examples describe that workflow using `sf` and tidyverse functions.

```r
cell_district <- st_centroid(fishnet) %>%
  st_join(police_districts %>% select(district = dist_num)) %>%
  st_drop_geometry() %>%
  select(cell_id, district)

fishnet <- fishnet %>%
  left_join(cell_district, by = "cell_id") %>%
  filter(!is.na(district))
```

What each step does:

- `st_centroid(fishnet)` represents each grid cell by a point at its centroid.
- `select(district = dist_num)` keeps the district identifier and renames it `district`. The polygon geometry remains attached to the `sf` object.
- `st_join()` assigns district attributes using the spatial relationship between the centroid and district polygons.
- `st_drop_geometry()` removes geometry after we have obtained the district identifier.
- `select(cell_id, district)` keeps a lookup table linking cell IDs to districts.
- `left_join(..., by = "cell_id")` attaches the district identifier to the original grid cells.
- `filter(!is.na(district))` removes cells without a matched district.

The centroid gives us a consistent way to assign a cell that overlaps a district boundary. It is still worth checking for duplicate assignments: a centroid exactly on a shared boundary, or overlapping district polygons, can match more than one polygon.

Both spatial layers need compatible coordinate reference systems. The cell ID connects the lookup table back to the original cells; row order is not the matching rule.

### Step 2: train and test one district at a time

```r
districts <- unique(fishnet$district)

cv_results <- map_dfr(districts, function(d) {
  train <- fishnet %>%
    filter(district != d) %>%
    st_drop_geometry()

  test <- fishnet %>%
    filter(district == d) %>%
    st_drop_geometry()

  fit <- glm(
    burglaries ~ cars_cnt + log_light_nn1 + log_graffiti_nn3 +
      loop_mi + dist_hotspot,
    family = poisson,
    data = train
  )

  test %>%
    mutate(pred = predict(fit, newdata = test, type = "response")) %>%
    summarize(
      district = d,
      n_cells = n(),
      mae = mean(abs(burglaries - pred))
    )
})
```

**Read `d` as “the district being held out this time.”**

`unique()` gets the district identifiers. `map_dfr()` runs the function for each identifier and stacks the returned rows into one table. `function(d)` is an anonymous function: it defines steps without assigning the function a separate name.

Inside each run:

- `district != d` means every district **except** the current one: training data.
- `district == d` means only the current district: test data.
- `glm(..., family = poisson)` fits the burglary-count model on the training data.
- `newdata = test` requests predictions for cells excluded from fitting.
- `type = "response"` returns expected burglary counts rather than log expected counts.
- `summarize()` returns one row for that held-out district.

The formula retains the predictor names from the class example. The `+` signs inside a model formula add predictors; they do not add the columns together into one predictor.

### What does MAE measure?

$$
\operatorname{MAE} = \frac{1}{n}\sum_{i=1}^{n}|y_i - \hat y_i|
$$

In `mean(abs(burglaries - pred))`, we subtract the predicted count from the observed count, take the absolute value of each error, and average those errors.

If a district's MAE were 2, its predictions would be off by an average of two burglaries per cell. This is an illustration of the units, not a result from the district data.

`n_cells` matters too. An error calculated from a small district fold may be less stable than one calculated from many cells.

### Step 3: map the errors

```r
police_districts %>%
  left_join(cv_results, by = c("dist_num" = "district")) %>%
  ggplot() +
  geom_sf(aes(fill = mae), color = "white") +
  scale_fill_viridis_c(name = "MAE") +

```

The join matches `dist_num` in the district polygons to `district` in the results. `geom_sf()` draws the polygons, while `aes(fill = mae)` maps prediction error to color.

This is a map of **where the model predicts poorly**, not a map of where burglary counts are highest. Those are different questions. Cross-validation also does not correct problems in how the outcome was recorded.

## Generalized linear models: keeping predictions within their limits

A **generalized linear model**, or GLM, combines:

1. A distribution for the outcome, conditional on its predictors.
2. A linear predictor, such as $z = \beta_0 + \beta_1x_1 + \beta_2x_2$.
3. A link function connecting the expected outcome to that linear predictor.

The word is **model**, not “module.”

### Link and inverse link

The **link function** transforms the expected outcome onto the scale of the linear predictor. The **inverse link** converts the linear predictor back into an expected count or probability.

| Model | Outcome | Expected value | Link: expected value to $z$ | Inverse link: $z$ to expected value |
|---|---|---|---|---|
| Poisson | A nonnegative integer count | $\mu > 0$ | $\log(\mu) = z$ | $\mu = e^z$ |
| Logistic | A binary value, 0 or 1 | $0 < p < 1$ | $\log\left(\frac{p}{1-p}\right) = z$ | $p = \frac{1}{1+e^{-z}}$ |

**Poisson uses an exponential inverse link. Logistic uses the sigmoid inverse link.** These are not interchangeable.

The probability or expected count can be non-integer even when the observed outcome is binary or a count. An expected count of 2.4 is valid; an observed count of 2.4 burglaries is not. A predicted probability of 0.7 is valid; the observed binary outcome is still 0 or 1.

For logistic regression, the link transforms the **probability**, not the observed zeros and ones. We do not manually take the logit of each observed 0 or 1 and fit an ordinary linear regression.

### Why not ordinary linear regression for this example?

An ordinary linear model can predict values below 0 or above 1 when fitted to a binary outcome. Such values cannot be interpreted as probabilities.

Logistic regression keeps the additive structure of the predictors but changes the scale on which that structure is modeled. Its inverse link produces valid probabilities.

“Linear” refers to the linear predictor. It does not mean that probability changes along a straight line as a predictor increases.

## Probability, odds, and log-odds

These are three ways to express related information. Keeping their scales separate makes the model easier to interpret.

### Probability

Probability compares the event to all possible outcomes:

$$
p = \frac{\text{events}}{\text{events} + \text{non-events}}
$$

A probability of 0.8 means 80 events per 100 cases in the corresponding frequency interpretation.

### Odds

Odds compare the event to the non-event:

$$
\text{odds} = \frac{p}{1-p}
$$

| Probability | Odds | Interpretation |
|---|---|---|
| $0.8$ | $0.8 / 0.2 = 4$ | Four events for every one non-event |
| $0.5$ | $0.5 / 0.5 = 1$ | One event for every one non-event: even odds |
| $0.1$ | $0.1 / 0.9 \approx 0.111$ | About one event for every nine non-events |
| $0.455$ | $0.455 / 0.545 \approx 0.835$ | About 84 events for every 100 non-events |

For the class data, the last row means about **84 people rearrested for every 100 people not rearrested**. It does not mean 84 out of every 100 people were rearrested.

To convert odds back to probability:

$$
p = \frac{\text{odds}}{1 + \text{odds}}
$$

Odds of 4 therefore correspond to $4/(1+4)=0.8$.

These formulas compare an event with its alternative. They do not tell us whether a previous event changes the probability of the next event; that requires information about how the events are related.

### Log-odds: the logit

Take the natural logarithm of the odds:

$$
\operatorname{logit}(p) = \log\left(\frac{p}{1-p}\right)
$$

In R, `log()` uses the natural logarithm by default. `exp()` reverses the natural logarithm.

```{r}
#| label: probability-odds-table
probability_ladder <- tibble(
  probability = c(0.01, 0.10, 0.50, 0.80, 0.90, 0.99)
) %>%
  mutate(
    odds = probability / (1 - probability),
    log_odds = log(odds)
  )

knitr::kable(probability_ladder, digits = 3)
```

For probabilities strictly between 0 and 1:

| Quantity | Range |
|---|---|
| Probability | Between 0 and 1 |
| Odds | Positive, with no upper limit |
| Log-odds | Any real number: negative, zero, or positive |

This last range matches what a linear predictor can produce.

- $p=0.5$ gives odds of 1 and log-odds of 0.
- $p<0.5$ gives odds below 1 and negative log-odds.
- $p>0.5$ gives odds above 1 and positive log-odds.

At probabilities exactly 0 and 1, the logit is not finite. A finite logistic linear predictor returns a probability strictly between those endpoints.

## From the linear predictor to the S-curve

The logistic model is:

$$
\log\left(\frac{p}{1-p}\right)
= \beta_0 + \beta_1x_1 + \beta_2x_2 + \cdots = z
$$

The inverse link converts $z$ to probability:

$$
p = \frac{e^z}{1+e^z} = \frac{1}{1+e^{-z}}
$$

These two expressions are equivalent. The resulting S-shaped curve is the **sigmoid**.

| Linear predictor | Predicted probability |
|---|---|
| $z<0$ | Below 50% |
| $z=0$ | Exactly 50% |
| $z>0$ | Above 50% |

A negative $z$ is valid. It is a negative **log-odds**, not a negative probability.

```{r}
#| label: sigmoid-curve
#| fig-cap: "The inverse logit converts any finite linear predictor into a probability between 0 and 1."
sigmoid_data <- tibble(z = seq(-6, 6, length.out = 301)) %>%
  mutate(probability = 1 / (1 + exp(-z)))

ggplot(sigmoid_data, aes(x = z, y = probability)) +
  geom_line(color = "steelblue", linewidth = 1) +
  geom_hline(yintercept = 0.5, linetype = "dashed", color = "grey50") +
  geom_vline(xintercept = 0, linetype = "dashed", color = "grey50") +
  scale_y_continuous(labels = scales::label_percent(), limits = c(0, 1)) +
  labs(
    title = "From log-odds to probability",
    x = "Linear predictor z (log-odds)",

  ) +

```

The curve is steepest in the middle and flatter near 0 and 1. The same increase in log-odds can therefore produce different changes in probability depending on where we start.

The distribution and the link have different jobs. The link connects the expected outcome to the predictors. The binomial distribution describes the binary outcome's variation around its probability. A person with a predicted probability of 0.78 still has an observed outcome of either 0 or 1.

## Fit the logistic regression

```{r}
#| label: fit-logistic-model
recid_fit <- glm(
  two_year_recid ~ age + priors_count + male + felony + juv_total,
  family = binomial,
  data = compas
)

summary(recid_fit)
```

- `glm()` fits a generalized linear model.
- The variable to the left of `~` is the outcome.
- The variables to the right are predictors.
- `family = binomial` uses the default logit link for this binary outcome.
- `data = compas` tells R where to find the columns.

Logistic regression estimates coefficients by **maximum likelihood**: it selects coefficients that make the observed sequence of zeros and ones most likely under the model. This differs from ordinary least squares, which minimizes squared residuals.

The class evaluates classification with confusion-matrix measures rather than relying on the usual OLS fit summary. A good training fit alone does not establish performance on new people.

- `type = "response"` applies the inverse link and returns probabilities.

## Read a coefficient three ways

### 1. Change in log-odds

The class model's coefficient for `priors_count` is about **0.160**.

Holding the other predictors fixed, one additional prior record is associated with an increase of about 0.160 in the log-odds of rearrest.

A coefficient is one contribution to the linear predictor. It is not the person's full predicted log-odds; that requires the intercept and all the predictor contributions.

### 2. Change in odds

Exponentiate a logistic coefficient to obtain an **odds ratio**:

$$
\text{odds ratio} = e^{\beta}
$$

```{r}
#| label: coefficient-odds-ratios
coefficient_table <- tibble(
  term = names(coef(recid_fit)),
  log_odds_coefficient = unname(coef(recid_fit)),
  odds_ratio = exp(unname(coef(recid_fit)))
)

knitr::kable(coefficient_table, digits = 3)
```

For `priors_count`, $e^{0.160} \approx 1.17$. One additional prior multiplies the odds by about 1.17, or increases the odds by about 17%, holding the other predictors fixed.

$$
\text{Percent change in odds} = (\text{odds ratio} - 1)\times100
$$

| Approximate result from class | Interpretation, holding other predictors fixed |
|---|---|
| Age: OR 0.96 | One more year of age is associated with about 4% lower odds |
| Prior records: OR 1.17 | One additional prior is associated with about 17% higher odds |
| Male indicator: OR 1.39 | The category coded 1 has about 39% higher odds than the reference category |
| Felony indicator: OR 1.26 | A felony charge has about 26% higher odds than the retained non-felony reference category |
| Juvenile records: OR 1.14 | One additional juvenile record is associated with about 14% higher odds |

These are rounded interpretations of fitted associations, not causal effects.

::: {.callout-important}
## Odds and odds ratios answer different questions

**Odds above 1** mean the event is more likely than the non-event: $p>0.5$.

**An odds ratio above 1** means the odds increase relative to the comparison. It does **not** mean the resulting probability exceeds 50%.

For example, odds can increase from 0.25 to 0.50. The odds ratio is 2, but the probability only rises from 20% to about 33.3%. Both probabilities remain below 50%.

Likewise, a positive individual coefficient does not guarantee that a person's full linear predictor is positive.
:::

Exponentiating a Poisson coefficient gives a multiplier for the expected count, or rate when exposure is handled appropriately. Exponentiating a logistic coefficient gives a multiplier for the **odds**. The calculation looks the same, but the interpretation differs.

### 3. Change in predicted probability

An odds ratio of 1.17 does not mean an increase of 17 percentage points, or necessarily a 17% increase in probability.

## From a probability to a decision

The model returns a probability. A threshold converts it to a binary label:

$$
\widehat{\text{class}} =
\begin{cases}
1 & \text{if } \hat p \geq t,\\
0 & \text{if } \hat p < t.
\end{cases}
$$

Here, $t$ is the threshold. A probability of 0.45 is labeled positive at a threshold of 0.30 and negative at a threshold of 0.50.

**Changing the threshold changes the decision, not the probability or the person's observed outcome.** It also does not refit the model.

A threshold of 0.50 is a common default, not a universal rule. The base rate gives context, but the consequences of errors and the available resources also matter.

```{r}
#| label: classify-at-thresholds
compas <- compas %>%
  mutate(
    pred_30 = as.integer(p_hat >= 0.30),
    pred_50 = as.integer(p_hat >= 0.50),
    pred_70 = as.integer(p_hat >= 0.70)
  )

table(
  predicted = compas$pred_30,
  actual = compas$two_year_recid
)
```

`p_hat >= 0.30` returns a logical result for each person. `as.integer()` changes `TRUE` to 1 and `FALSE` to 0. A probability exactly equal to the threshold is classified as positive here.

## The confusion matrix

A confusion matrix compares the predicted label with the actual recorded outcome.

| | Actual positive: rearrested | Actual negative: not rearrested |
|---|---|---|
| Predicted positive: flagged | True positive (TP) | False positive (FP) |
| Predicted negative: not flagged | False negative (FN) | True negative (TN) |

“Positive” means the outcome coded 1. It does not mean good, desirable, or morally positive.

- **TP:** we flagged someone who was rearrested.
- **FP:** we flagged someone who was not rearrested.
- **FN:** we did not flag someone who was rearrested.
- **TN:** we did not flag someone who was not rearrested.

R's `table()` usually displays 0 before 1. Use the row and column labels to identify the cells rather than memorizing a position on the page.

### Sensitivity, specificity, precision, and accuracy

| Measure | Formula | Question |
|---|---|---|
| Sensitivity | $TP/(TP+FN)$ | Of everyone actually positive, how many did we catch? |
| Specificity | $TN/(TN+FP)$ | Of everyone actually negative, how many did we correctly leave unflagged? |
| Precision | $TP/(TP+FP)$ | Of everyone we flagged, how many were actually positive? |
| Accuracy | $(TP+TN)/(TP+FP+FN+TN)$ | Of all cases, how many labels were correct? |

Sensitivity and precision both have `TP` on top, but they answer different questions:

- Sensitivity starts with **all actual positives**.
- Precision starts with **all predicted positives**.

Using the disease analogy: sensitivity asks how many sick people we caught; precision asks how many people sent to quarantine were actually sick.

## The classroom threshold exercise

Each participant had a predicted disease probability. A red dot indicated actual disease, and a star indicated the severe variant. Moving people to the quarantine area represented classifying them as positive.

The numerical example below is the **40-person example in the slides**. The spoken activity used the people present in class, so its counts should not be combined with this table.

```{r}
#| label: classroom-threshold-results
classroom_results <- tibble(
  threshold = c(0.30, 0.50, 0.70),
  TP = c(14, 10, 7),
  FP = c(13, 6, 2),
  FN = c(2, 6, 9),
  TN = c(11, 18, 22),
  stars_caught = c("3 of 4", "2 of 4", "1 of 4")
) %>%
  mutate(
    sensitivity_pct = TP / (TP + FN) * 100,
    specificity_pct = TN / (TN + FP) * 100,
    precision_pct = TP / (TP + FP) * 100,
    accuracy_pct = (TP + TN) / (TP + FP + FN + TN) * 100
  )

classroom_results %>%
  select(threshold, TP, FP, FN, TN, stars_caught) %>%
  knitr::kable()

classroom_results %>%
  select(threshold, ends_with("_pct")) %>%
  knitr::kable(digits = 1)
```

At a threshold of **0.30**, we catch 14 of the 16 sick people, but also quarantine 13 people who are not sick.

At **0.70**, we quarantine only two people who are not sick, but miss nine of the 16 sick people.

Accuracy is highest at 0.70 in this example, even though that threshold misses the most sick people. **The highest overall accuracy does not automatically give the most appropriate decision.**

One starred case is missed at all three tested thresholds. Lowering the threshold further might catch that case, but also flag many more people. Changing the cutoff does not improve the model's ordering of cases or correct the underlying predicted probabilities.

### What changes when we move the threshold?

For a fixed set of predicted probabilities:

| Threshold change | Predicted positives | Sensitivity | Specificity |
|---|---|---|---|
| Lower the threshold | More, or the same number | Increases or stays the same | Decreases or stays the same |
| Raise the threshold | Fewer, or the same number | Decreases or stays the same | Increases or stays the same |

Precision and overall accuracy do not have to move in one direction as the threshold changes.

```{r}
#| label: sensitivity-specificity-plot
#| fig-cap: "In the slides' classroom example, a higher threshold catches fewer sick people and correctly leaves more non-sick people unflagged."
classroom_results %>%
  select(threshold, sensitivity_pct, specificity_pct) %>%
  pivot_longer(
    cols = ends_with("_pct"),
    names_to = "measure",
    values_to = "percent"
  ) %>%
  mutate(measure = recode(
    measure,
    sensitivity_pct = "Sensitivity",
    specificity_pct = "Specificity"
  )) %>%
  ggplot(aes(x = threshold, y = percent, color = measure)) +
  geom_line(linewidth = 0.8) +
  geom_point(size = 3) +
  scale_x_continuous(breaks = c(0.3, 0.5, 0.7)) +
```

## The same trade-off in the rearrest model

The following calculation repeats the comparison at 0.30, 0.50, and 0.70. These are predictions for the same observations used to fit this illustrative model. They are **training-sample results**, not held-out cross-validation scores.

```{r}
#| label: rearrest-threshold-results
threshold_results <- map_dfr(c(0.30, 0.50, 0.70), function(t) {
  predicted <- compas$p_hat >= t
  actual <- compas$two_year_recid == 1

  tibble(
    threshold = t,
    flagged = sum(predicted),
    TP = sum(predicted & actual),
    FP = sum(predicted & !actual),
    FN = sum(!predicted & actual),
    TN = sum(!predicted & !actual)
  )
}) %>%
  mutate(
    sensitivity_pct = TP / (TP + FN) * 100,
    specificity_pct = TN / (TN + FP) * 100,
    precision_pct = TP / (TP + FP) * 100,
    accuracy_pct = (TP + TN) / (TP + FP + FN + TN) * 100
  )

threshold_results %>%
  select(threshold, flagged, TP, FP, FN, TN) %>%
  knitr::kable()

threshold_results %>%
  select(threshold, ends_with("_pct")) %>%
  knitr::kable(digits = 1)
```

Here, `&` means both conditions must be true, while `!` reverses a logical condition. For example, `predicted & !actual` identifies false positives. Adding logical values with `sum()` counts the `TRUE` cases.

The slide results illustrate the trade-off:

- At **0.30**, 4,843 people are flagged, including **2,316 who were not rearrested**. There are **282 false negatives**.
- At **0.50**, 2,264 people are flagged. There are **713 false positives** and **1,258 false negatives**.
- At **0.70**, 710 people are flagged. There are **147 false positives**, but **2,246 false negatives**.

A higher threshold reduces false positives by also leaving more actual positives unflagged. The model cannot tell us which consequence we should prioritize.

## Attach a policy decision to the label

The class compared two possible uses of the same probability:

| Use | What being flagged means | Concern about false positives | Concern about false negatives |
|---|---|---|---|
| Restrictive action | Detention or denial of release | Restricting someone who did not experience the recorded outcome | Missing someone who did experience it |
| Supportive action | An offer of housing help, a job program, or a case worker | Using limited program capacity on additional people | Failing to offer support to people who may benefit |

The costs of errors are different across these uses. A lower threshold flags more people and may be appropriate for a broad offer of support if resources allow it. A restrictive action raises much more serious concerns about false positives, and the program itself may need to be questioned.

A person who was not rearrested does not necessarily have no need for support. Similarly, the observed outcome does not tell us what would have happened under a different intervention. Prediction alone does not establish the effect of providing services or detention.

The classroom discussion also asked whether a threshold could make both kinds of error disappear. Moving the threshold usually trades one type of error against another. Choosing a cutoff therefore requires a clear understanding of the action, the consequences, and whose costs count.

**The threshold is a policy choice. `glm()` does not make that choice for us.**

### Leaving race out is not the same as removing bias

Race is not a predictor in this class formula. That alone does not establish that the model is race-blind or fair. Other variables can be associated with race, and arrest records reflect how the outcome was observed and recorded.

This was raised as a question for further discussion. ROC curves were also introduced as the next topic; this week's exercise compared a few thresholds directly.

## Things to keep straight

| Easily confused ideas | Distinction |
|---|---|
| Random CV and geographic CV | Random folds mix locations; geographic folds hold out areas |
| Link and inverse link | The link maps the expected outcome to the linear predictor; the inverse maps back |
| Poisson and logistic inverse links | Poisson uses $e^z$; logistic uses $1/(1+e^{-z})$ |
| Probability and odds | Probability compares events with all cases; odds compare events with non-events |
| Odds and odds ratio | Odds describe one probability; an odds ratio compares two odds |
| Coefficient and full linear predictor | One coefficient is one contribution; the full predictor includes all contributions and the intercept |
| 17% higher odds and 17 percentage points | These are different changes on different scales |
| Probability and predicted class | A class depends on a chosen threshold |
| Sensitivity and precision | Sensitivity starts with actual positives; precision starts with predicted positives |
| Accuracy and an appropriate decision | Accuracy counts correct labels; an appropriate decision also considers the consequences of errors |
| Rearrest and crime | The data record rearrest; they do not observe all criminal behavior |
